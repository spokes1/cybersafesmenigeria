## 1. Implementation summary

The former short Incident Response article, which prescribed one generic "first hour, in order", has been replaced at the **same route** by the complete owner-approved 8 November 2026 action-first article. All approved reader-facing prose, the short wholesale-business example, Nigerian reporting channels, nuanced account/payment/device/data advice, conditional NDPA Section 40 wording, the Start Here action, four related destinations and disclaimer are present. No extra story disclosure or story-reading-time label was introduced.

The new **First-Response Switchboard** is located directly inside the approved "What happened?" section, with a hero shortcut for quick access. It has four semantic buttons: **Money, Accounts, Devices and Customer information**. Every category provides "The situation", "What to do first", "What to preserve" and "Who to contact", plus a link to the corresponding complete incident-specific response. Only one summary is spotlighted when JavaScript initialises; with JavaScript unavailable, all four summaries remain in the document and readable. Buttons expose a truthful `aria-pressed` state and visible focus; no incident data is collected.

The five-step **First-Response Card** preserves the sequence **Pause, Protect, Report, Record, Recover** and the approved action phrases. A browser Print button is available when JavaScript loads. Print CSS hides navigation and unrelated article sections and prints the whole card in a high-contrast, white format; the card can also be printed with JavaScript disabled using the browser print command. No downloadable PDF or new service dependency is introduced.

Visual design uses the existing light palette, Plus Jakarta Sans and line icons. No third-party workplace photograph was licensed or added; the hero instead uses a compact CSS/icon reference illustration. The article retains its own emergency-reference information hierarchy rather than repeating the Ransomware Board or Malware Warning Desk.

## 2. Reading-time audit

- **Finished normally visible page:** approximately **2,515 words**, measured in offline Chromium using the actual enhanced page's `innerText` with one selected Switchboard summary.
- **Method:** 2,515 / 220 words per minute = 11.43, rounded **up to 12 minutes**.
- **Displayed hero label:** **12-minute read**.
- **Optional hidden story:** none. The short fictional "Three calls in one morning" example is ordinary visible text; **no Read More** or extra minutes appear.
- **Draft difference:** the editorial handoff estimated 11 minutes from the article alone. The published page also includes the visible Switchboard summary, response-card framing and hero text. No approved text was shortened to retain the draft's reading-time estimate.
- **No-JavaScript view:** shows all four Switchboard summaries rather than one. This intentionally provides more visible reference material than the default interactive presentation.

`docs/READ_TIME_AUDIT_2026-11-08.csv` preserves the earlier 18-topic audit and adds previously implemented Ransomware and the new Incident Response as topics 19 and 20. The 7 November historical register is retained unchanged.
